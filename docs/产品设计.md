# 只此一间 v2 — 产品设计说明

## 一、产品定义

**一句话：一个只属于你们两个人的、有记忆的、安静的空间。**

微信是日常聊天的地方（不动它）。这里是"值得被记住的东西"沉淀下来的地方。

AI 不是分析师，是那个记得所有事、嘴很严、偶尔在合适的时候轻轻说一句话的朋友。

> 世界很大，我们只拥有这一间。

---

## 二、不是什么

- ❌ 情侣打卡 / 任务工具
- ❌ AI 关系分析 / 情绪评分 / 健康度报告
- ❌ 聊天软件替代品
- ❌ "深聊话题生成器" / "AI 故事日更"
- ❌ 需要改变日常习惯的 App

## 三、是什么

- ✅ 两人共享的记忆体（文字 / 图片 / 语音）
- ✅ 语义搜索：用自然语言翻旧账
- ✅ AI 静默关联：自动把相关记忆串起来
- ✅ 特定时刻的温柔提醒（纪念日、记录周年）
- ✅ 完全本地、私密、自主可控

---

## 四、AI 的角色（清晰边界）

| # | AI 做什么 | 何时 | 用户感知 |
|---|----------|------|---------|
| 1 | **记住 & 关联** — 理解存入的内容，与旧记录建立语义联系 | 每次存入时后台静默执行 | 无感。不打标签、不显示分数 |
| 2 | **找回来** — 自然语言语义检索，从所有记录中捞回相关内容 | 用户主动搜索/提问时 | "去年冬天那张雪的照片" → 返回结果 |
| 3 | **在合适的时刻说一句** — 纪念日、记录周年等触发 | 特定条件（见 §八） | 很轻：一句话 / 一张卡片，不是报告 |

### AI 不做的事

- ❌ 情绪打分 / 重要度评分
- ❌ "关系健康度"分析
- ❌ 主动生成建议（"你们应该多沟通"）
- ❌ 编造叙事故事（除非用户主动要求）
- ❌ 任何让用户感到"被观测"的行为

## 五、功能清单

### 5.1 日常记录（高频，< 3 秒完成）

| 操作 | 方式 |
|------|------|
| 记一句话 | 打开客户端（DSH 面板 / 手机）→ 粘贴/打字 → 发送 |
| 记一张图 | 拍照 / 相册选图 → （可选附文字）→ 发送 |
| 记一段语音 | 按住说话 → 松手发送（后台转文字，可被搜索） |

> 没有"选择类型"、没有表单。就是发一条消息的感觉。

### 5.2 翻旧账（中频）

| 功能 | 说明 |
|------|------|
| 时间线浏览 | 按天/周分组的记录流，图片缩略图 + 文字摘要 + 语音播放条 |
| 语义搜索 | 输入框打自然语言 → AI 检索 → 返回相关记录列表 |
| 关联展示 | 点进一条记录，底部显示"相关的还有：……"（AI 自动关联 2-3 条） |

### 5.3 特定时刻（低频，AI 主动）

| 触发条件 | 表现 | 频率 |
|---------|------|------|
| 在一起纪念日 / 生日前 1 天 | 首页卡片 + 订阅消息推送："明天是第 N 天。去年今天你存了：……" | 一年一次 |
| 某条记录满 1/2/5 年 | "一周年了：'那天下了好大的雨……'" | 每条最多触发一次 |
| 连续 7 天未记录 | 打开客户端时首页一行轻提示（不推送） | 仅打开时显示 |

> **核心原则：不推送、不打扰。只有你们打开时才在。** 纪念日那种一年一次的可以推一条订阅消息。

### 5.4 设置

| 功能 | 在哪做 |
|------|--------|
| AI 模型配置（Provider / URL / Model / Key） | DSH Slot 面板 |
| 主题/风格管理（预设 + 自定义上传） | DSH Slot 面板 |
| 绑定管理（生成链接、查看状态） | DSH Slot 面板 |
| 数据导出（JSON + 媒体打包下载） | DSH Slot 面板 |
| AI 总开关（关掉 = 纯存储+时间线） | DSH Slot 面板 |
| 个人头像/昵称 | 客户端设置界面 |
| 主题切换（轻量：选预设色） | 客户端设置界面 |

## 七、技术架构

### 7.1 总体拓扑

> **v2 架构变更（2026-08，已实现）**：从「FastAPI 后端进程 + 薄客户端插件」改为「**插件即应用**」。
> 整个后端（`node:sqlite` 数据层 + 业务逻辑 + AI 网关 + 媒体存储）收敛进 DSH 进程的 host half，
> **不再 spawn 独立后端、不再监听端口、不再需要 Cloudflare 隧道**。
> 数据落在稳定目录（缺省 `~/.dsh/only-room/`），换机器 = 拷这个目录。
> 下方拓扑图的 FastAPI/cloudflared 部分为 v1 历史，v2 实际以"插件即应用"为准（见 README「架构」一节）。

### 7.2 AI Gateway（零死代码原则）

**统一接口，配置驱动：**

```python
class AiGateway:
    async def chat(self, messages: list[dict], **opts) -> str
    async def embed(self, texts: list[str], **opts) -> list[list[float]]
    async def transcribe(self, audio_path: str, **opts) -> str
```

**Provider Adapter（可插拔）：**

| Adapter | 支持范围 |
|---------|---------|
| `ollama` | Ollama native API（/api/chat, /api/embeddings, whisper） |
| `openai_compat` | 任何 OpenAI 兼容端点：vLLM、LM Studio、DeepSeek、Moonshot、OpenAI、Ollama /v1…… |

**配置来源（优先级从高到低）：**
1. DSH Slot 面板设置页修改 → 写入 `data/ai-config.json`
2. `data/ai-config.json` 默认值

```jsonc
// data/ai-config.json
{
  "chat": {
    "provider": "ollama",              // "ollama" | "openai_compat"
    "base_url": "http://localhost:11434",
    "api_key": "",                     // openai_compat 时填
    "model": ""                        // 空 = 自动检测（仅 ollama）
  },
  "embed": {
    "provider": "ollama",
    "base_url": "http://localhost:11434",
    "api_key": "",
    "model": "nomic-embed-text"
  },
  "transcribe": {
    "provider": "whisper_local",       // "whisper_local" | "openai_compat"
    "model_size": "small",             // tiny/base/small/medium/large
    "language": "zh"
  }
}
```

**原则：业务代码永远只调 `gateway.chat()` / `gateway.embed()` / `gateway.transcribe()`，不知道也不关心底下是谁。换模型 = 改 JSON。加新 provider = 写一个 adapter 文件。**

### 7.3 数据模型（SQLite）

| 表 | 说明 |
|----|------|
| `users` | id, wechat_openid, nickname, avatar_url, created_at |
| `rooms` | id, name, user1_id, user2_id, anniversary_date, created_at |
| `memories` | id, room_id, user_id, content_type(text/image/audio), text, media_path, transcript(语音转文字结果), embedding_ref, recorded_at, created_at |
| `room_settings` | room_id, key, value（主题配置、AI 开关等） |

> 相比 v1：去掉了 stories / deep_talk_topics / relationship_insights / invitations / custom_assets 表。绑定改为链接机制，不再需要邀请码表。

### 7.4 向量检索（ChromaDB）

- 每条 memory 存入时计算 embedding → upsert 到 ChromaDB
- 搜索时：query text → embed → cosine similarity top-K → 返回相关记录
- 关联展示：取当前记录的 embedding → 查最近邻 2-3 条 → "相关的还有"

### 7.5 网络层（Cloudflare Tunnel）

> **v2**：不再需要本节。v2 没有监听端口、没有独立后端，远程访问由 **DSH 宿主本身**的远程能力承担（DSH 支持 Web 远程访问时，设置页的「只此一间」面板自然可远程用），不再是本插件的职责。以下为 v1 历史。

| 组件 | 说明 |
|------|------|
| `cloudflared` | 迷你主机上常驻进程，出站连接 Cloudflare，无需公网 IP / 端口映射 |
| 域名 | `room.yourname.com`（或任意自有域名），CNAME 到 `xxx.cfargotunnel.com` |
| HTTPS | Cloudflare 自动证书 |
| 安全 | 客户端合法域名配置（如需）+ API Token 认证（房间级） |

> 远程客户端：浏览器/小程序/App 请求 `https://room.yourname.com/api/*` → Cloudflare 隧道 → 本地 FastAPI。

### 7.6 移动端客户端（微信 / 原生 App，未来可选）

| 项 | 说明 |
|----|------|
| 类型 | 企业自建（个人主体也可注册），**不公开发布**，仅体验成员可用 |
| 框架 | 原生小程序 / Taro（看开发效率） |
| 页面 | 时间线、搜索、关于、设置（4 页） |
| 主题 | CSS 变量驱动，从 API 拉取当前房间主题配置 |
| 录音 | `wx.getRecorderManager()` → 上传到 `/api/memories/upload` |
| 图片 | `wx.chooseMedia()` → 上传 |
| 推送 | 订阅消息（纪念日等，需用户提前授权） |

### 7.7 DSH Cordis Plugin

| 层 | 职责 |
|----|------|
| **Host half（`index.js` + `lib/`）** | **自包含整个应用**：① `node:sqlite` 数据层（rooms/memories/settings）；② 业务逻辑（`lib/repo/*`）；③ AI 网关（`lib/ai/gateway.js`，按需调用，未配可降级）；④ 向量库 + 媒体存储；⑤ 暴露受信任路由 `POST /only-room/api`（RPC，全部数据操作）+ `GET /only-room/media`（媒体） |
| **Client half（`client/client.js`）** | DSH GUI 内嵌面板：快速记录 + 最近列表 + AI 配置（DSH 格式）+ 主题管理 + 绑定/导出按钮 |

> **v2**：插件**就是**业务逻辑本身（不再有外部 FastAPI）。客户端（DSH 面板 / Web / 小程序）通过同一套 RPC 契约（`POST /only-room/api`）接入，接口保持稳定、可插拔。

## 八、AI 主动时刻（详细规则）

| 触发 | 条件 | 行为 | 推送方式 |
|------|------|------|---------|
| 在一起纪念日 | `anniversary_date` 的月日 = 明天 | 首页卡片 + "去年今天你存了：……"（从该日期附近取一条记录） | 可选推送（如微信订阅消息，需授权） |
| 生日 | 对方 birthday 字段 = 明天 | 同上 | 订阅消息 |
| 记录周年 | 某条 memory 的 `recorded_at` 满整年（1/2/5 年）且未触发过 | "一周年了：'……'" | 不推送，下次打开时显示在"关于"页 |
| 沉默提醒 | 连续 7 天无新记录 | 首页一行："已经一周没记录了哦。" | 不推送，仅打开时显示 |

**频率控制：** 每个触发器对同一条记录/同一个日期最多触发一次（用 `room_settings` 表记已触发的 key）。

## 九、安全 & 隐私

| 维度 | 措施 |
|------|------|
| 数据位置 | 全部在迷你主机本地，不出机器（除非用户主动配了云端 AI endpoint） |
| 传输加密 | Cloudflare Tunnel = WireGuard 级加密隧道 + HTTPS |
| API 认证 | 房间级 Token（创建房间时生成），所有客户端请求携带 |
| 身份 | 设备级 client_id（跨平台通用，无需微信 openid / 邮箱 / 密码），经 bind 关联进房间成员 |
| 访问控制 | 只有绑定进该 room 的成员 client_id 能读写其数据 |
| 备份 | DSH 面板"导出"= 打包 SQLite + media → 下载 zip |

## 十二、设计原则（写代码时的约束）

1. **零死代码 / 零硬编码** — Provider、模型名、路径全部配置驱动；不存在 `if provider == "ollama"` 散落在业务层
2. **AI 是隐形的** — 用户看不到"分析中…"、不显示情绪标签/分数；关联和检索的结果以自然的方式呈现
3. **轻到不用就消失** — 记录动作 < 3 秒；没有打卡、没有任务、没有通知轰炸
4. **数据主权** — 所有数据在本地，用户随时可完整导出带走
5. **客户端可插拔** — RPC 契约（`POST /only-room/api`）是唯一数据源与契约；DSH 面板是当前客户端，Web/小程序是未来可选客户端。客户端换、应用不动，不重复建设
